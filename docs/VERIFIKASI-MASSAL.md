## Keputusan implementasi
- Semua berarti baris pada halaman antrean aktif (maksimum 50 terlihat, endpoint maksimum 100), bukan seluruh hasil lintas halaman. Filter form/unit/periode dikirim bersama snapshot domain/id/row_version. Server memeriksa kecocokan filter di dalam kunci transaksi dan tidak mencari daftar tambahan.
- Satu `withActor()` + `review()` per item; status/versi berubah, item sendiri, filter tidak cocok atau akses hilang dilewati. Kesalahan lain dilaporkan gagal dan proses berlanjut. Override tidak diterima pada endpoint massal; admin tetap dapat memakai jalur tunggal beralasan.
- Satu audit ringkasan berisi aktor/request, aksi, jumlah, filter ID/domain dan alasan reject; tanpa payload domain/nama/pengaju. Bila audit ringkasan gagal setelah item commit, respons tetap melaporkan hasil sebenarnya dan peringatan audit, tidak mengaku rollback.
- Dialog native dengan jumlah dan rincian form/unit/periode, alasan reject wajib, konfirmasi eksplisit, kontrol dinonaktifkan selama proses. Hasil per item memakai textContent.
- Baseline sebelum kode: 24 domain dev dan 68 berkas terlindungi, `.runtime/xlsx-diag/{dev,protected}-bulk-before.json`. Mutasi tes hanya `_test`; tidak menjalankan reset atau mengubah data approved dev.

## Kontrak dan batas operasional
- `GET /api/verification/filters` dan `/submissions?domain=...&unit_id=...&periode_laporan_id=...`: admin/PRP saja, no-store; antrean tetap submitted dengan limit/offset existing.
- `POST /api/verification/bulk-approve` atau `/bulk-reject`: `{confirmed:true, filter:{domain?,unit_id?,periode_laporan_id?}, items:[{domain,id,row_version}], review_note?}`. ID dinormalisasi, item duplikat ditolak, 1–100 item; reject membutuhkan alasan trim 1–2000 karakter. Body strict menolak override dan field tambahan.
- Respons memuat `results` (domain/id/versi/outcome/code/alasan), `counts` (success/skipped/failed), status audit dan request ID. Error internal tidak memuat SQL/detail DB. Ringkasan audit satu event `bulk_approve`/`bulk_reject`; audit per item tetap `approve`/`reject` dari trigger existing dengan request ID yang sama.
- Dialog mengunci snapshot halaman aktif; paging lain tidak disertakan. Item sendiri tidak menjadi kandidat UI dan dijelaskan pada hitungan; server tetap melewati item sendiri jika dikirim langsung. Untuk override admin, gunakan review tunggal beralasan seperti sebelumnya.
- Anggaran pemrosesan 30 detik sebelum memulai item berikutnya, timeout socket route 60 detik dan klien 75 detik. Item yang belum dimulai setelah anggaran habis dilaporkan gagal/belum diproses. Gangguan koneksi menampilkan hasil belum dapat dipastikan dan meminta pengecekan riwayat; tidak ada retry tulis otomatis. Guard versi/status memastikan pengiriman ulang tidak menggandakan approval item.
